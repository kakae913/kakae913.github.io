## 1. IDS (Intrusion Detection System, 침입 탐지 시스템)

네트워크 트래픽이나 시스템 로그를 실시간으로 모니터링하다가 해킹 징후나 보안 정책 위반을 탐지하면 관리자에게 경보를 알려주는 수동적인 보안 시스템이다.

**동작 방식:** 주로 스위치의 미러링(Mirroring) 포트 등을 통해 복제된 트래픽을 받아 분석한다. (Out-of-Path 구성)

*스위치: 같은 네트워크 안에 있는 컴퓨터, 서버 등의 기기들을 하나로 연결해주고 각 기기들이 보내는 데이터를 정확한 목적지로 전달해주는 네트워크 장비*

**특징:**

- 트래픽의 흐름을 직접 가로막지 않으므로, 장비에 장애가 생기거나 오탐(False Positive)이 발생해도 정상적인 네트워크 서비스에는 지장을 주지 않는다.
- 공격을 탐지하더라도 즉각적인 차단이 불가능해, 관리자가 경고를 확인하고 방화벽 정책을 수정하는 등 후속 조치를 취하는 동안 피해가 발생할 수 있다.

## 2. IPS (Intrusion Prevention System, 침입 방지 시스템)

IDS의 탐지 기능에 능동적인 차단 기능을 추가한 보안 장비이다. 악성 트래픽이 탐지되면 즉시 패킷을 드롭(삭제)하거나 세션을 끊어 공격을 차단한다.

- **동작 방식:** 네트워크 경로상에 직접 배치(In-line 구성)되어 모든 트래픽이 IPS를 통과하도록 한다.
- **특징:**
  - 제로데이 공격이나 웜(Worm)처럼 확산 속도가 빠른 위협에 실시간으로 대응할 수 있다.
  - 정상 트래픽을 공격으로 잘못 판단하는 오탐(False Positive)이 발생하면 정상 사용자의 접속까지 차단될 수 있으며, 장비 장애 시 전체 네트워크가 마비될 위험이 있어 바이패스(Bypass) 기능이 중요하다.

| 구분 | IDS (침입 탐지 시스템) | IPS (침입 방지 시스템) |
| --- | --- | --- |
| 핵심 목적 | 침입 탐지 및 경고 (사후 대응 중심) | 침입 탐지 및 실시간 차단 (사전 예방 중심) |
| 배치 구조 | Out-of-Path (미러링 / 탭 방식) | In-line (네트워크 경로상 직접 연결) |
| 대응 방식 | 수동적 (로그 기록, 관리자 알림) | 능동적 (패킷 드롭, 세션 종료, IP 차단) |
| 오탐(False Positive) 영향 | 관리자 피로도 증가 (서비스 영향은 적음) | 정상 서비스 장애 유발 가능 |
| 네트워크 지연(Latency) | 거의 없음 (복제본 분석) | 발생 가능 (패킷 검사 후 전달) |

## 3. 탐지 방식

### 3-1. 시그니처 기반 탐지 (Signature-based)

이미 알려진 해킹 공격의 특징을 시그니처 데이터베이스에 저장해 두고, 들어오는 트래픽과 비교해 일치하면 공격으로 판단하는 방식이다.

- **예시:** 패킷 데이터에 SQL 인젝션이나 XSS와 관련된 특정 문자열 패턴이 포함되어 있는지 검사한다.
- **장점:** 알려진 공격을 정확하게 탐지할 수 있고 오탐이 적다.
- **단점:** 데이터베이스에 등록되지 않은 새로운 공격(Zero-day 공격)이나 패턴을 교묘하게 변형한 공격은 탐지하지 못할 수 있다. 따라서 시그니처를 꾸준히 업데이트해야 한다.

### 3-2. 이상 행위 기반 탐지 (Anomaly-based Detection)

평소의 정상적인 트래픽 기준을 학습하고, 그 기준에서 크게 벗어나는 상황이 생기면 공격으로 판단하는 방식이다.

- **예시:** 평소 하루에 100건 정도 발생하던 특정 포트 접속이 갑자기 1초에 10,000건씩 늘어나거나(DDoS), 새벽 3시에 내부 직원의 PC에서 외부 IP로 대용량 데이터가 전송되는 경우가 있다.
- **장점:** 시그니처가 없는 신종 공격(Zero-day)이나 내부자 위협을 탐지할 수 있다.
- **단점:** 이벤트나 프로모션으로 정상 트래픽이 갑자기 몰리는 상황도 공격으로 오인할 수 있어 오탐률이 높다.

### 3-3. 상태 기반 프로토콜 분석 (Stateful Protocol Analysis)

단일 패킷만 따로 보는 것이 아니라, 네트워크 통신 프로토콜(TCP, HTTP, DNS 등)의 정상적인 동작 규칙과 연결 상태를 추적해 규칙을 어긴 행위를 탐지하는 방식이다.

- **예시:**
  - 정상적인 TCP 연결 과정인 3-Way Handshake(SYN → SYN/ACK → ACK)를 완료하지 않은 상태에서 갑자기 데이터를 보내거나 연결 종료(FIN) 패킷을 보내는 경우.
  - HTTP 규격에 맞지 않게 비정상적으로 긴 헤더를 보내거나, 로그인 인증 상태를 거치지 않고 관리자 페이지에 접근을 요청하는 경우.
- **장점:** 특정 공격 문자열만 찾는 것이 아니라 통신의 흐름과 프로토콜 규칙 위반을 확인하므로, 패킷을 교묘하게 쪼개거나 우회하려는 공격을 탐지하는 데 도움이 된다.
- **단점:** 많은 사용자의 연결 상태(세션 정보)를 실시간으로 기록하고 추적해야 하므로 CPU와 메모리 자원을 많이 사용할 수 있다. 표준에서 벗어났지만 정상인 트래픽을 공격으로 오인할 수도 있다.

## 4. IDS와 IPS의 유형

### 4-1. NIDS (Network-based Intrusion Detection System)

네트워크 전체를 오가는 패킷을 복사해 감시하다가 포트 스캐닝이나 외부 해킹 시도가 보이면 관리자에게 경보를 보낸다.

### 4-2. HIDS (Host-based Intrusion Detection System)

서버나 PC 내부의 시스템 로그, 중요 파일 변조 여부(무결성 검사), 레지스트리 변경, 비정상적인 프로세스 실행 등을 감시해 이상 징후가 있으면 알린다.

### 4-3. NIPS (Network-based Intrusion Prevention System)

네트워크를 통과하는 악성 패킷(DDoS, 웜, SQL 인젝션 등)을 실시간으로 분석해 차단한다.

### 4-4. HIPS (Host-based Intrusion Prevention System)

개별 기기 내부에서 악성코드가 실행되거나 시스템 핵심 파일이 수정되는 등 의심스러운 행위를 감지해 운영체제 수준에서 차단한다.

### 4-5. WIPS (Wireless-based Intrusion Prevention System)

Wi-Fi 같은 무선 네트워크 환경에서 비인가 접근이나 의심스러운 무선 통신을 탐지하고 대응한다. 사내에 몰래 설치된 비인가 공유기, 정상 Wi-Fi로 위장한 가짜 AP, 무선 네트워크 공격 등을 탐지하고 통제하는 데 활용한다.

## 5. 궁금했던 점

**Q1.** NIDS나 NIPS는 데이터가 오가는 네트워크 길목(In-line)이나 옆길(Out-of-Path)에 있어서 패킷을 감시할 수 있다는 게 이해가 된다. 그런데 개별 기기 내부에 설치되는 HIDS나 HIPS는 어떤 방식으로 내부 움직임을 감시할까? 네트워크처럼 패킷이 오가는 것도 아닌데, 시스템 로그가 바뀌거나 악성코드가 실행되는 순간을 어떻게 포착하고 차단할 수 있지?

**A1.** 호스트 내부에서는 프로그램과 운영체제(OS) 커널이 주고받는 명령(시스템 콜) 등을 감시 지점으로 활용할 수 있다. HIDS/HIPS는 에이전트나 운영체제의 보안 기능을 이용해 파일 수정과 프로세스 실행 같은 행위를 기록하거나 감시한다. 설정과 제품에 따라 의심스러운 행위를 알리거나 차단할 수 있다.
